## 先纠正我之前的错误

我上一轮说"DeepSeek 不支持图片"——**这是错的**。官方现在有完整的 Vision 指南，
`deepseek-chat` 和 `deepseek-flash` 都支持图片输入。

真正的原因是**我的代码没把图送过去**：

1. 取消息时用的是 `extract_plain_text()`，这个方法**只取文字**，图片段被直接扔掉；
2. 请求体里的 `content` 一直是纯字符串，**从来没构造过图片块**。

所以不是你配置错了，也不是模型不行，是图压根没到模型面前。

## 技术实现

### 1. 从 QQ 消息里取图

QQ 的图片段长这样，里面带一个 http 链接：

```json
{"type": "image", "data": {"file": "abc.jpg", "url": "https://gchat.qpic.cn/...", "summary": "[动画表情]"}}
```

现在会把这个 `url` 提取出来，而不是当作没看见。

### 2. 本地下载后转 base64（关键一步）

QQ 图床有防盗链、链接还会过期，**直接把链接丢给模型，服务端经常抓不到**。
所以先在本地下载，再转成 `data:image/png;base64,...` 内联发过去。

- 格式按**文件头**判断（JPEG / PNG / GIF / WebP），不信扩展名
- 单图上限 8MB，一次最多 3 张
- 下载失败 → 降级为直接传原链接
- 还失败 → 当作没有图片，纯文字回答

### 3. 请求体结构

```python
{
  "role": "user",
  "content": [
    {"type": "text", "text": "这图什么意思"},
    {"type": "image_url", "image_url": {"url": "data:image/png;base64,...", "detail": "low"}}
  ]
}
```

用 `detail: low` 会先把图缩到 512×512，表情包足够用，**更便宜也更快**。

### 4. 安全

图片链接同样走 SSRF 校验：内网、本机、云服务器元数据地址的图片链接**一律拒绝**，
防止有人借机器人探测你的内网。

## 已知限制

- **动图 GIF 只按单帧理解**：接口支持 GIF，但不做逐帧/时间轴分析，
  所以"这个动图什么意思"能看懂大致画面，但抓不住动作细节
- **需要登录的图床会失败**：部分外链图（如某些网盘/私密相册）下载不到，此时会降级传链接
- **不保存图片**：只在这一轮请求里内联，不落盘、不建索引
